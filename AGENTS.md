# LMA repository instructions / 仓库工作约定

- Work inside this repository and the user's designated `无审查小模型/` directory. Do not invoke Docker, WSL, virtual machines, or Android emulators. 使用原生工具，不调度任何虚拟化环境。
- Close all browser pages, contexts, and browser processes created for a task in `finally` blocks. 浏览器调用结束必须关闭不用的页面并释放内存。
- LMA is a local-model workbench with Hugging Face discovery across model repositories; selection is not restricted to uncensored variants. Preserve exact weight attribution and compatibility boundaries. Give Uncensored / Abliterated variants a separate tag, distinguish checked publisher declarations from metadata-only hints, and never present all HF formats as Android-compatible. 用户已要求本地模型定位和完整 HF 发现流程；无审查仅作为独立标签，自定义导入不得冒充已核对条目。
- **All inference and multimodal workflow stages must execute on the same Android phone.** HF/network access may download model assets before execution; never add remote/LAN/cloud inference providers, external execution nodes or off-device fallbacks. Missing assets, unsupported backends and resource limits must fail locally with an explanation. Keep source review, upstream phone reports and LMA device evidence separate. 用户要求全部本机运行；分词、编码器、生成、codec、媒体合成均在手机，不能以其他设备替代，也不把本机回环通信误认为外部推理。
- Prioritize a shared extensible multimodal foundation: model/component/recipe descriptors, versioned engine adapters, capability-based routing, per-model schemas, persistent jobs/artifacts and local task execution. Supported variants should reuse the foundation; new architectures must have explicit adapters rather than model-ID-specific UI/queue branches. 用户当前核心目标是可持续接入图像、视频、音频模型的共用基座；架构支持与手机可运行范围分别验收。
- Current expansion scope is selections **01–14, 16, 17**, governed by [the bilingual release plan](docs/MULTIMODAL_RELEASE_PLAN.md) and [scope/tags](docs/proposals/multimodal-release-scope.json). Every model is an equal peer with output-task and foundation-dependency tags. Use model selection, capability-specific forms, the shared queue and artifacts. Do not build ComfyUI wiring, infinite canvas, public user nodes, a plugin ecosystem or graph import; internal versioned engine adapters remain required. Requirements/registered assets are not execution support; family subtargets require individual offline phone evidence. 用户最新范围不含 ComfyUI 体系；所有模型平级，标签分类；内部引擎模块不等于用户插件系统。
- The next release is **one complete v0.3.0 delivery**: F-01–F-12, existing text, and runtime/recipe support for selections 01–14/16/17, every frozen subtarget and both SD 1.5/SDXL LoRA. Do not split these into later versions or automatically defer failed targets. Internal work ordering is allowed; all work packages share the same release gates. Open required targets remain blockers for this version, and a reduced preview is not completion. 用户要求下一版本一次完成全部基座与所选模型，取消分版工作线路；风险不等于顺延授权。
- **App updates deliver the foundation; users control model assets.** APKs contain no model weights/model-specific data. Installation/upgrades/browsing must not trigger model downloads or silently replace weights. Download only explicitly selected bundles and disclosed required dependencies; preserve existing user models/settings and offer independent pause/resume/import/update/delete. Catalogue/recommendations are metadata, not preinstalled models. Validate coverage with developer test assets without making those user prerequisites; include A11 acceptance. 用户明确 App 仅更新基座，模型用户自主选择 / 下载 / 管理；生文 / 生图 / 生视频 / 生音频标签与安装状态独立。
- Preserve Recommended as `m08 → m06 → m01` with its existing order, labels and pinned evidence. Discover other HF models through All/search; use Local to manage every downloaded source and unfinished transfer. 用户明确要求保留既有推荐，仅扩展“全部 / 搜索”，并增加“本地”栏目。
- Keep inference settings per model ID, edited through Local with editable presets. Enforce GGUF context metadata, shared context/output bounds and device/application ranges in both UI and native code; label unknown metadata honestly. 模型参数独立保存，超限归位，旧版全局值迁移；全局设置只保留应用偏好。
- Keep private keys, passwords, API keys, model weights, build caches, and personal browser profiles out of Git, source archives, logs, screenshots, and releases. Preserve the existing local `signing/` files for APK upgrades.
- Describe desktop checks, interface fixtures, and actual Android acceptance separately. Never claim phone inference, tokens/s, refusal-rate measurements, or background endurance without corresponding device evidence.
- **For every subsequent authorized LMA update, synchronize the code, Chinese and English READMEs/guides, relevant screenshots/GIFs, `CHANGELOG.md`, and version-specific release notes before committing and pushing to `git@github.com:wikigsroom/LMA.git`.** This is the user's standing instruction. 后续更新必须同步更新代码、双语文档、相关演示与更新说明并推送；远端受阻则保留本地提交并明确说明。
- Publish a new APK release only with consistent version fields, current verification fingerprints, APK/source hashes, validation records, and the original signing identity. Never replace an existing release asset with different bytes under the same filename; use a new version.
- Existing Git history and remote branches must be preserved. Do not force-push or rewrite published tags.
- Follow [CONTRIBUTING.md](CONTRIBUTING.md) and [docs/RELEASING.md](docs/RELEASING.md) for the concrete update workflow. Do not infer a request for background scheduling from the synchronization instruction.
- End every development turn with numbered tables of the concrete work implemented this turn and the remaining work. Distinguish source implementation, scoped checks, physical-device acceptance and complete Release readiness; preserve the full frozen scope in the pending table. 用户要求每轮开发结束用编号表格列出本轮实现事项及待处理 / 待完成事项。
