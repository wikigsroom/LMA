## Concrete discrepancies found and fixes inspected

These are defects in the initially reviewed shared bindings, not claims that all P05 implementation was present. They were reported to the implementing agent and corrected there. No production edits were made by this reviewer.

| # | Initial mismatch and consequence | Current source-backed correction |
|---|---|---|
| F01 | Initial upsample/C2S branches discarded the spatial cache after one inverse and preferred a provided guide over existing cache. A second inverse in down/down/up/up or S2C/S2C/C2S/C2S could fail or use different support. This contradicts source `spatial/basic.py:L85-L106` and `spatial2channel.py:L70-L92`. | Cache now takes precedence and survives the cached inverse: `spatial_portable.py:L268-L275,L286-L294`. The new test uses two levels plus an intentionally all-false supplied guide (`test_portable_sparse_models.py:L69-L88`). Explicit uncached guide expansion correctly does not inherit the old topology cache, matching source. |
| F02 | Source D10 supplies int32 coordinates in the public pipeline (`D10/supratex/inference/pipeline.py:L256`; observation construction `inference/native_observation.py:L482`). Initially the join binding passed them directly to a native int64-only operator, and the symbolic output could inherit the observed coordinate dtype despite row indices being int64. | Both join arguments convert to `.long()` at `spatial_portable.py:L187`; symbolic rows explicitly have int64 type at `spatial_sparse_graphs.py:L130-L133`. Native ABI is int64 at `native/spatial/sparse_ort.hpp:L16,L50-L59`. New code checks int32 source calls, reversed observed order, non-subset and duplicate rejection (`test_portable_sparse_models.py:L120-L129`). |
| F03 | The initial replacement config defined `CONV`/`DEBUG` but omitted `BATCH_BROADCAST`, which the retained `VarLenTensor` and `SparseTensor` torch-tensor arithmetic reads (`D10/supratex/modules/sparse/basic.py:L203,L720`; source default `modules/sparse/config.py:L6`). Per-batch `+/-/*` therefore raised before export. | `BATCH_BROADCAST='direct'` is now set at `spatial_portable.py:L81`. New arithmetic checks cover sparse and varlen containers (`test_portable_sparse_models.py:L73-L77`). This API defect was concrete; the D10 final interleaved forward mostly operates on `.feats`, so it was not evidence that every final-model call necessarily hit the broken branch. |
| F04 | Initially `attention` stripped dense batch axes only when Q was 4D. Source cross attention permits sparse Q `[N,H,C]` with dense context producing K/V `[1,L,H,C]` (`D10/supratex/modules/sparse/attention/modules.py:L127-L138`; D05 has the same route). Even B=1 then reached a native operator requiring all Q/K/V to be 3D (`native/spatial/sparse_ort.hpp:L32-L36`). Dense Q with sparse K/V was also handled incorrectly. | Each Q/K/V is now independently packed, with batch-one assertion on any dense tensor; the output follows the original query container/rank (`spatial_portable.py:L199-L216`). Actual `SparseMultiHeadAttention(type='cross')` cases exercise both two-argument and normalized three-argument routes (`test_portable_sparse_models.py:L89-L99`). The final D10 interleaved sparse/sparse route is unaffected by this specific mixed-rank defect. |

Each initial discrepancy was sent to the implementing agent before correction. All four corrected paths were reread against the final snapshot above. Earlier working copies are not retained by this report, so the reproducible code-side evidence is the final file hashes and exact source comparisons.
