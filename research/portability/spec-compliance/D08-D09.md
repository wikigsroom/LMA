**What this demands of an implementation:**

A selected SAM bundle must have an actual local execution path from an image and mask through a matched MoGe pointmap stage, source-defined image/mask/pointmap normalization and conditioning, the multi-head MoT sparse-structure/layout model, occupancy decoding and coordinate processing, pose decoding, sparse SLAT generation, the chosen geometry/appearance decoders, FlexiCubes and GLB writing. Pointmaps, model evaluation and output conversion must run on the Android device. A supplied pointmap can be an additional input mode; requiring an off-device depth precomputation does not satisfy the baseline local pipeline (`docs/REMAINING_ADAPTATION.md:L42`; executed SAM path `P8/inference_pipeline_pointmap.py:L403-L462`).

MV-SAM3D requires this same backbone plus actual multi-image DA3 depth/camera inference, consistent ordered view/image/mask/pointmap/camera data, per-view conditions evaluated against a shared state at each integration step, source-defined fusion, attention-weight collection and warmup/main-pass semantics. Four independently generated objects or the existing Pixal3D four-view network cannot stand in for this model (`P9/inference_pipeline.py:L964-L1007`, `L1693-L1782`; `P9/multi_view_utils.py:L135-L187`).

The minimum declared output profile must be explicit. Upstream `decode_slat` can select `mesh`, `gaussian`, or `gaussian_4`, but its GLB postprocessor indexes `outputs["gaussian"][0]` whenever `mesh` exists. Consequently `decode_formats=["mesh"]` by itself does **not** make the upstream full `run` path a valid mesh-only export. A separate local mesh/vertex-color GLB postprocessor is needed for that subset; equivalence to Gaussian-rendered texture baking requires its own actual renderer/baker (`P8/inference_pipeline.py:L543-L555`, `L609-L614`).

8. **D09 weighted SLAT:** `run_multi_view` selects weighted versus plain multi-view SLAT at `P9/inference_pipeline.py:L1746-L1782`. Weighted mode runs one warmup step, collects attention and sparse downsample mappings, computes weights and expands them to original coordinates (`L1352-L1454`). Visibility/mixed options use a callback supplied with the decoded object pose; callback failure is fatal for visibility-only and falls back to entropy for mixed (`L1404-L1435`). It then generates fresh initial noise, fixes that tensor for the full pass, restores the noise generator in `finally`, builds sparse features and denormalizes (`L1456-L1520`). ### Tensor contracts grounded in source

`B` is batch, `V` ordered views, `N` active sparse sites, `T_k/C_k` the matched named latent's actual token/channel dimensions. Export contracts below retain these symbols where the selected release config is unavailable. The actual SLAT wrapper consumes `x[0]` and returns `h.feats[None]`; the initial supported export/runtime profile must explicitly use **B=1** unless separate batching is implemented and checked (`B/models/structured_latent_flow.py:L340-L354`).

### Source-specific correctness points for the port

1. **Coordinate convention:** DA3 script unprojects `x=(u-cx)z/fx, y=(v-cy)z/fy, z=depth` (`D09/scripts/run_da3.py:L75-L88`). Actual D09 external-pointmap branch applies the same camera transform as MoGe, described there as `(-x,-y,z)` (`P9/inference_pipeline_pointmap.py:L276-L308`). It does **not** perform an extra Y/Z flip. The `run_multi_view` docstring at `P9/inference_pipeline.py:L1559` says already-PyTorch3D, and comments at `L1652-L1653` suggest a different flip; these conflict with the called implementation. Port the executed branch and lock it down with asymmetric point/camera fixtures.
2. **SS warmup/replay:** save CPU and CUDA RNG states before warmup, discard its terminal sample, restore those states, restore full step count, then run the weighted main pass (`P9/inference_pipeline.py:L1091-L1169`). A fresh unrelated main SS noise tensor changes this method's semantics.
3. **SLAT warmup/replay:** one warmup step collects attention and downsample maps (`P9/inference_pipeline.py:L1352-L1399`). This method does **not** restore its pre-warmup RNG state. It draws new main-pass noise after warmup, then pins that tensor through `_generate_noise` replacement and restores the method in `finally` (`L1467-L1512`). Do not impose the SS replay rule on SLAT and call it exact upstream behavior.
4. **Attention weights:** SS uses normalized crop-image entropy and cross-view softmax, alpha 60 and .001 minimum in that helper (`P9/multi_view_weighted.py:L236-L323`). SLAT's source defaults differ: alpha 30, minimum .01, temperature 1, layer 6 (`D09/sam3d_objects/utils/latent_weighting.py:L76-L121`, `L602-L628`). Missing/mismatched weights must take an explicit supported fallback or fail validation, not silently broadcast a wrong coordinate count (`P9/inference_pipeline.py:L1441-L1454`). Visibility and mixed modes are extra actual algorithms with DDA/camera callback requirements (`.../latent_weighting.py:L630-L724`; `P9/inference_pipeline.py:L1404-L1435`).
5. **Sparse budgets:** upstream downsample trigger is 42,000 sites, with centering, rounding, uniqueness and random cap (`P8/inference_utils.py:L653-L718`). Existing shared CPU limits are 262,144 sites and 32,000,000 feature values (`LMA/native/spatial/sparse.hpp:L14-L15`). Two full eight-child subdivisions would allow at most 4,096 input sites under that existing point cap, far below the upstream 42,000 cap; 42,000×768 also exceeds its feature-value cap. A full profile needs streamed/chunked stages or explicitly revised capacity guards, not silent coordinate loss or a false claim that these helpers already cover the released network.
