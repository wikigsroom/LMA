# 原有文本模型迁移与资产复用

[English](MODEL_MIGRATION.en.md) · [文本任务](TEXT_ENGINE.md) · [版本管理](MODEL_UPDATES.md) · [完整需求](MULTIMODAL_RELEASE_PLAN.md)

适用：**0.3.0-dev.10 / code 14，内部开发检查点，未发布完整 v0.3.0**。已下载的原有文本 GGUF 可纳入共用模型包、独立参数、任务和版本管理，不需要重新下载。迁移本身不选择、加载、更新或替换模型，也不连接模型下载服务。

## 用户流程

1. 保留应用数据升级。App 在后台检查已有完整文件；正在加载或运行的旧文本模型会等待停止，进程退出后再次检查。
2. 继续在“推荐 / 全部 / 本地”查看原条目。推荐顺序 `m08 → m06 → m01`、原模型 ID、来源与已核对的内容标签保持；同一模型不增加重复卡片。
3. 迁移完成后，详情出现“创建生成任务”和“模型版本管理”，复用现有文件。用户明确允许尝试未测配方并提交后，共用任务等待当前回复，自动回收并切换引擎；空闲恢复用户仍希望运行的文本模型。见[调度指南](SCHEDULING.md)。
4. 原设置入口和共用包设置访问同一份模型配置。正文输出参数用于后续请求；加载参数变更会重载进程，正在回复时拒绝变更。上下文与输出同时受实际 GGUF、配方、设备和应用限制约束。
5. 未完成的 `.part` 下载继续保留，重启 / 升级后显示暂停。用户明确点击继续才恢复传输。导入文件保留导入属性，不虚构可下载地址。
6. 模型由用户独立更新 / 删除；排队任务、运行进程和其他模型的共享引用会保护仍需使用的资产。App 升级不要求更新权重。

可选择不安装模型，继续浏览 App。迁移失败时原文件和记录保持可管理，错误不会触发重新下载或外部推理。由于没有物理 Android 验收，不能将此流程当成手机升级已验证的承诺。

## 数据与中断处理

旧存储的 `models-state.json` 保留目录、自定义 / HF 来源和旧独立配置，增加原 ID 到不可变包 ID 的 `bindings`。包 ID 由原 ID 和内容 SHA256 确定；模型版本切换不重定向已有 API ID 或任务。

`BundleStore.adoptLocal` 是共用资产能力：只接受完整已存在文件，按固定清单校验，在私有 partial 目录创建临时硬链接，验证其真实字节后才发布 CAS 对象与安装记录。模型内容不重写，不创建网络传输；相同 SHA256 的组件可以复用。文件系统不允许硬链接时保留原文件并报错。

发布 CAS 后，迁移在请求锁下重新检查原文件与运行状态，采用用户在校验期间保存的最新参数，再以 AtomicFile 提交绑定、参数和 metadata。绑定提交后才移除旧私有文件名；崩溃留下的原文件或未引用对象仍可恢复。启动只清理本机制产生的 `.adopt-UUID` 临时链接，保留正常续传 `.part`。

HF 文件保留固定仓库、revision、路径和发布者哈希；没有固定 HF revision 的旧地址不会被虚构为可复现来源。自定义无哈希文件先测量 SHA256，仍不获得发布者核对或设备验证标签。迁移不能继承其他模型的 Uncensored / Abliterated 声明。

持久文本进程持有同一模型包租约，实际进程退出才释放。受信任的引擎所有者可修改后续默认参数；已提交任务的参数快照与不可变文件清单保持。普通设置 / 删除仍遵守运行与队列引用保护。

## API 与证据边界

`GET /v1/models` 保留原文本 ID，并增加 `bundle_id` 供异步 `text.generate` 任务使用；不额外返回同一已迁移包的重复模型行。同步聊天 / completion API 使用用户选定的文本模型，并可等待共用执行槽；完整物理设备调度验收仍待完成。新任务客户端须明确使用返回的不可变包 ID。

本检查点新增 **69 项主机检查**：真实文件 / 硬链接、GGUF metadata、HF / 导入来源、并发默认参数、取消 / 中断恢复、共享删除、API ID、真实子进程及租约。界面总计 **156 项**。数据为零 tensor GGUF 和固定协议内容，无模型推理。见[迁移回执](../verification/development/migration.json)、[开发状态](DEVELOPMENT.md)和[更新说明](releases/v0.3.0-dev.9.md)。
