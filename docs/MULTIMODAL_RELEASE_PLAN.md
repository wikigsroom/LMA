## 01 · 决策与范围冻结

**下一版本 v0.3.0 一次性交付完整共用本地基座，以及全部所选 16 组模型的运行支持与适配配方，不拆分版本、不默认顺延。** 原生管线、算子、共享内存、设备与许可风险属于本版需要解决的工作；风险未关闭时保留为本版阻塞项，不转写成后续版本计划，也不把需求纳入等同于已实现。

- v0.3.0 纳入原编号 **01–14、16、17** 及其全部冻结子目标，编号不重新分配。既有文本模型继续保留，计入生文能力，不要求重新选型。SD 1.5 和 SDXL LoRA 均在本版验收。
- 不纳入原编号 15 YuE2、18 大 Wan、19 新 LTX、20 H3、21 ComfyUI 体系；也不做模型训练 / LoRA 训练。
- 所有模型记录平级。功能、引擎依赖、格式、设备适配和安装状态通过标签 / 筛选表达；不建立“文本模型之下的多模态子模型”或引擎文件夹树。
- 全部生成在同一 Android 手机执行，无需 ROOT、Termux、外部推理服务或转换服务。HF 网络用于显式下载；安装资产后新输入必须可断网生成。
- 内部引擎适配器和固定管线仍是必要实现，但不建设面向用户的节点 / 插件体系，不导入 ComfyUI 图。

**“支持”必须包括完整包、真实引擎、正确参数、手机离线生成、产物可打开、取消与卸载、后台归属和可复查设备证据。** 加标签、显示仓库、下载权重、配置一个尚不可运行的 provider，都不算已经支持。实验支持也必须至少有真实输出，不能用实验标签代替运行结果。

这 16 项是需求分组，不是 16 个权重文件；03、10、12 特别包含多个子目标。整体完成意味着所有冻结子目标均完成，不用 09 Nano 替代 12，也不用静态图编码替代 16 / 17。

### App 更新与用户模型资产的边界

**App 更新仅交付基座，模型资产由用户自主选择、下载、导入、管理和删除。** “本版支持全部目标”指对应架构、引擎、配方与管理流程可用，不表示将全部模型打入 APK、预装到手机或要求用户全部下载。

| 对象 | 交付 / 管理规则 |
| --- | --- |
| APK 基座 | 界面、引擎 / 后端代码、任务 / 后台 / API、通用资源、标签规则、目录元数据、配方与许可说明；不含模型权重 |
| 模型相关数据 | 主权重、LoRA、编码器 / VAE / 音频 codec 权重，以及模型专用 tokenizer / 音色 / 语言包等，由用户选择后单独下载或导入 |
| 新安装 / App 升级 | 不自动选择模型，不因安装 / 升级下载任何模型资产；保留既有文件、模型配置和用户已授权的管理偏好，不静默替换权重 |
| 用户下载 | 展示所选模型 / 量化 / 配方的必需组件、总大小、可复用组件和设备要求；用户点击下载才为这套包创建任务，不扩展到其他推荐或同家族模型 |
| 独立管理 | 可只装一个或任意所需组合；支持暂停 / 续传、独立更新 / 导入 / 删除。删除模型不卸载 App 基座；共享组件删除保护仍生效 |
| 无模型状态 | 可以启动 App、浏览目录和标签、管理设置；生成与模型 API 要求用户已有兼容模型，缺失时提示选择 / 下载，不隐式下载或转出手机 |

功能标签描述模型能力，安装状态描述手机实际资产，两者独立。推荐是候选条目，不是自动下载清单。“14 个内置条目”仅指预置目录元数据，权重仍由用户选择。App 升级不强制更新模型；已支持架构的兼容权重可以独立下载，新增架构 / 算子仍可能需要更新基座。

开发验收可以按测试计划下载样本模型，验证 16 组支持能力；这些资产不进入发布 APK，也不成为终端用户安装前提。所选支持范围、单版本交付和真实执行验收要求保持不变。

## 02 · 平级模型与标签规范

所有生文 / 生图 / 生视频 / 生音频模型共享同一种 `ModelRecord`：稳定 ID、名称、来源 / revision、任务能力、可选配方、组件依赖、独立配置、安装与兼容状态。任务页面按选中模型的真实能力展示输入，不按模型“等级”决定入口。

| 标签维度 | 例子 | 规则 |
| --- | --- | --- |
| 功能 / 输出类型 | `task:text` 生文、`task:image` 生图、`task:video` 生视频、`task:audio` 生音频 | 可多选；按输出能力标记，TTS 不因输入文字而获得生文标签 |
| 具体能力 | `text_to_image`、`text_to_speech`、`text_to_sound`、`text_to_video`、`image_adapter` | 仅对已声明配方生效；语音克隆、图像编辑、图生视频等不自动继承 |
| 引擎需求 | `engine:sd_cpp`、`engine:mnn_diffusion`、`engine:sherpa_tts` | 有替代引擎时表达 OR；不能把 sd.cpp / MNN 误标为必须同时安装 |
| 管线 / 格式 / 组件 | `pipeline:wan21_13b`、`format:gguf`、`dependency:audio_codec`、`dependency:vae` | 按具体配方计算。GGUF / safetensors 不表示通用可运行，混合组件可有多种格式 |
| 硬件 / 运行条件 | `backend:vulkan`、`backend:cpu`、QNN SoC / QAIRT / 编译形状 | 需求、探测结果和测量值分开；只为实际选中的路线显示必需项 |
| 状态 | 待适配、缺组件、已安装、待验证、实验已测、设备已验证、不兼容 | 架构能力、包安装、设备实测为不同字段，不用一个“支持”布尔值混合 |
| 许可 / 内容 / 证据 | 对应许可；Uncensored / Abliterated；作者声明 / 元数据线索 | 与功能和设备状态独立；新模型不自动继承无审查标签 |

“全部 / 搜索 / 本地”是同一平级模型池的视图；“推荐”保留 `m08 → m06 → m01` 和原标签，是人工筛选视图，不是模型层级。功能标签作为筛选，不额外建立四套模型管理和下载器。

LoRA 也有平级条目，标“生图适配器 / 需基础模型”，点击使用时选择匹配基础模型，不伪装成独立生成模型。依赖图是技术关系，不是界面父子等级。编码器 / VAE / codec 等默认作为组件库资源；用户单独导入组件时明确角色，不给它虚假的生成能力。

家族规划记录可以汇总能力，但实际发布的每个 checkpoint 独立打标签。例如 MOSS SoundEffect 不自动获得 TTS 标签。未知 HF 模型保留“能力待识别 / 暂无配方”；来源 metadata 提示与已核对能力分开。

示例：Wan 条目显示“生视频 · 文生视频”，详情显示需要 Wan 管线、UMT5 / VAE 和适用后端；MOSS Nano 显示“生音频 · TTS”，详情显示 tokenizer / codec；二者与既有 Qwen 文本模型平级。计划 JSON 中的标签是需求标签，**没有修改生产目录或声称引擎已安装**。

## 03 · 基座完整需求

| 需求 ID | 必须交付 | 完成标准 |
| --- | --- | --- |
| F-01 平级模型库 | 共用记录、标签 / 筛选、详情、HF 来源和本地管理 | 所有模态共用 ID / 搜索 / 下载入口；保留推荐 |
| F-02 模型包 | 多组件、固定 revision / SHA256、共享引用、续传、原子安装与删除保护 | 缺一个必需组件不进入可执行状态；运行中不可清理输入 |
| F-03 配方与能力 | 架构 / 引擎 / 后端分层，已编译能力和版本匹配 | 能说明为什么不可运行；未知算子 / 设备不盲目放行 |
| F-04 内部引擎模块 | 生命周期协议、工作进程、版本与依赖锁、崩溃隔离 | 本版所选配方必需模块全部可执行，空适配器不算完成；原生代码随签名 APK 更新，模型下载只提供数据 |
| F-05 独立参数 | 每模型 / 配方 schema、可编辑预设、超限回填和联合约束 | 文本上下文、图像尺寸 / 步数、视频帧数、音频参数互不污染；保存有效值与原因 |
| F-06 任务与队列 | 异步提交、排队、取消、事件、进度、有限重试 | 单任务输入和状态持久化；取消绑定任务与进程代次 |
| F-07 资源准入 | 分阶段内存、共享 RAM、磁盘、线程 / GPU 配方与热管理 | 默认一个大型引擎；已测预算 / 未知估算明确区分；不静默转出或换模型 |
| F-08 后台与恢复 | 前台服务、可见通知、停止入口、按需锁、重启对账 | 界面退出不主动取消；只有真实 checkpoint 才能续步，否则明确重跑该阶段 |
| F-09 结果库 | 图片 / WAV / 视频预览、参数 / seed / 来源、保存与导出 | 产物带 hash 和完整配置快照；静态图短片和生成运动视频明确区分 |
| F-10 API | 保留文本 API，新增本机异步任务 / 事件 / 取消 / 鉴权产物接口 | UI 与 API 共用调度和参数校验；不把视频响应塞成文本流 |
| F-11 发行与迁移 | 原生 Windows NDK / CMake 构建、ABI / SDK / 依赖、签名、版本迁移与回归 | 不调度 Docker / WSL / 模拟器；旧模型、历史、配置不丢；每版源码 / APK / 证据一致 |
| F-12 证据与维护 | 精确模型 / 引擎 / 设备矩阵、错误 / 资源记录、双语文档与功能媒体 | 桌面替身、上游报告与本机实测分别记录，不能互相代替 |

不做无限画布、连线编辑、用户节点、插件市场、第三方 Python 节点和 ComfyUI JSON 导入。内部可使用简单阶段依赖调度完成编码 / 采样 / 解码，但无需对用户暴露通用 DAG，也不把旧 JSON 草案当作执行接口承诺。

## 05 · 家族子目标与本版可行性风险

**03：** SD-Turbo（SD 2.1）、LCM checkpoint、LCM-LoRA 各验一条匹配基础模型的路线；不能跑通其中一个就声称全部完成。**10：** Kokoro、Piper、Matcha 各固定一套可发布语言 / 音色包并验收；这不意味着支持其所有语言和第三方声音。

**12：** 按本轮发布方清单冻结九个本版必需子目标：MOSS-TTS 1.0、v1.5、Local-Transformer、Local-Transformer-v1.5、TTSD-v1.0、VoiceGenerator、SoundEffect、SoundEffect-v2.0、Realtime；Nano 已归 09。它们涉及 Delay、Local、Realtime 和独立 DiT 路线，不能共用一个未验证的“全 MOSS 开关”。上游全原生 Delay 分支还实现音频编码 / 解码，可作为移植起点，但不证明这些架构全部 Android 可用。[发布方家族表](https://github.com/OpenMOSS/MOSS-TTS#released-models)、[原生 Delay 管线](https://github.com/OpenMOSS/llama.cpp/blob/moss-tts-firstclass/docs/moss-tts-firstclass-e2e.md)

**13：** SoulX 官方仍以 Linux / Python 参考管线为依据，部分 ONNX 文件不能代替完整 Android host loop、分词、参考编码、codec 和多说话人时序。[SoulX 模型卡](https://huggingface.co/Soul-AILab/SoulX-Podcast-1.7B) 12 / 13 都是明确纳入、但必须过原生原型关卡的需求；尚不能保证最终手机资源与质量合格，失败不得伪报完成或自动删出范围。

**06 / 07 / 08：** 量化主干之外还要计算编码器、VAE、激活和系统内存；按较新高内存手机先做探测。Qwen-Image-2.1 不能只按 7B 估算整条链，其 Qwen Research License 也不能继承旧版 Apache 条件。[Qwen 组件](https://github.com/leejet/stable-diffusion.cpp/blob/master/docs/qwen_image_2.1.md)、[模型许可](https://huggingface.co/Qwen/Qwen-Image-2.1)

**11：** 有 LiteRT Kotlin 和原生 Android 参考，但示例 App 的 API 要求及是否实时分别验证；已有 Pixel 8a 的上游测试尚未实时，不能承诺 Z20 实时。**14：** LiteRT 路线生成短音效 / 音乐片段，不宣传整曲创作。[Qwen TTS Android](https://github.com/google-ai-edge/litert-samples/tree/main/samples/litert/text_to_speech_lm)、[Arm 音频部署](https://developer.arm.com/code-along/stable-audio-open-small)

**16 / 17：** 已有实现作者的 Android 路线，可做真正的本机生视频实验。Wan 1.3B 的磁盘参数 / CPU 编码与 VAE / Vulkan diffusion 仍需移植，不能把其桌面 CUDA 时间写成手机结果。旧 LTX 2B 的 QNN 包不包含 Z20，Vulkan 独立验证；LLM-Hub 代码的非商业条件和 QNN / 模型再分发条件必须解决，不能整包纳入 MIT LMA。[Wan 实现](https://github.com/SaientAI/saient/blob/main/docs/VIDEO_PIPELINE.md)、[LTX 转换包](https://huggingface.co/timmyboy26/LTX-Video-2B-0.9.8-distilled-QNN)、[代码许可](https://github.com/timmyy123/LLM-Hub/blob/main/LICENSE)

完整源码与其他模型依据见 [MULTIMODAL.md](MULTIMODAL.md)。所有许可关卡针对实际选中组件，不把开源模型宣传语作为商用 / 分发结论。

## 06 · 用户使用逻辑

1. 安装 / 升级 LMA 只更新基座，不预装或触发模型下载；已有用户模型和设置保留。进入统一模型库，保留推荐，也可按生文 / 生图 / 生视频 / 生音频、名称、安装或兼容状态筛选。没有模型仍能浏览和管理 App。
2. 用户自行进入模型详情，选择模型 / 量化 / 配方，查看功能标签、完整组件、总下载、可复用数据和设备状态，点击下载才创建所选包的任务；浏览与推荐不触发下载。缺引擎时说明所需基座版本，不让权重下载代替引擎支持。
3. 在“本地”管理全部模型及传输，编辑该模型独立参数。LoRA 通过匹配基础模型选择器使用，依然是平级条目。
4. 点击使用，显示对应任务表单：提示词 / 文本、所需输入文件、可用音色 / 说话人、尺寸 / 帧数 / 时长。只展示当前配方支持的字段，缺少必填输入时明确说明。
5. 原生校验并回填参数，显示调整原因与最终值；提交到共用队列。页面报告阶段、可用进度、真实预览和取消；没有引擎进度就不编造百分比。
6. 在结果库查看 / 播放 / 导出，复制有效配置或重新生成。锁屏后由前台服务持有任务，重新打开恢复记录；中断按实际引擎能力处理。

本版不增加自由组合自动化编辑器。图片旁白合成等若后续提供，仅用固定产品表单 / 内置步骤，不由旧草案推导为额外必做功能。

## 07 · 发行边界与设备覆盖

Android 9 / API 28、ARM64 作为应用基线；部分新引擎 / 硬件包可以有更高 API，逐配方声明并禁用不适配路线。Z20 优先验证 01 / 02 / 09 / 10，其他条目以专项或较新设备为目标，不承诺 16 组全部在 Z20 可用。较新高内存手机与芯片特定 QNN 是测试分组，不是未经测量的统一最低 RAM。

网络关闭时，分词、文本编码、参考音频处理、采样、VAE / codec、播放与导出都须能完成新任务。模型不足时报告本机原因；内部回环通信及手机向调用者提供 API 都不改变推理地点。

前台服务无需 ROOT，但厂商省电、低内存、系统终止和发热仍可能中断。持续 API / 排队生成的后台验收与模型生成质量分别记录；不能保证 24/7 满载或不受 Android 服务时限影响。服务类型按真实任务 / Android 版本配置。[后台约束](WORKFLOWS.md)

开发构建已加入通过原生 Windows NDK / CMake 编译的扩散与语音 worker，并保留预编译文本 / ORT 依赖。其余引擎仍需各自编译依赖、ABI / 页尺寸检查和许可打包；现有构建成功不能代替全部目标与设备验收。模型 / 引擎版本与签名 APK 对应，模型数据里不放可执行脚本。

## 10 · 验收清单与“完整”判定

- **A1 模型平级：** 四种功能筛选来自同一数据池；推荐 ID / 顺序 / 标签不变；LoRA 与生成模型平级且明确依赖；未知 HF 不能被误标可用。
- **A2 标签：** 所有目标及子目标具备功能 / 基座标签；替代引擎 OR、混合组件格式、不同后端和版本限制正确；标签不替代实测状态。
- **A3 包安装：** 缺文件、SHA 不符、续传、暂停、磁盘不足、共享组件删除、运行中引用、升级中断均有真实可解释状态。
- **A4 参数：** 模型间独立、旧值迁移、可编辑预设、硬上限回填、未知上限标识、联合尺寸 / 帧数 / 固定形状校验、有效配置快照。
- **A5 执行：** 对冻结目标用网络关闭后的新输入生成可打开结果；图像非占位图、音频不是预制示例、视频不是静态图转码；连续至少三次短任务检查重载 / 释放。
- **A6 生命周期：** 排队、切换模型、取消 / 卸载、工作进程崩溃、UI 重建、锁屏、省电、发热与中断恢复；不能伪造没有 checkpoint 的续步。
- **A7 后台：** 记录至少一次覆盖锁屏 15 分钟的任务或队列，以及持续服务 1 小时的空闲 / 请求交替测试；更长测试另记实测时长，不推导为永久保证。
- **A8 资源与质量：** 每配方记录 SoC / RAM / Android / 驱动、组件哈希、引擎构建、参数、峰值共享内存、耗时、音频 RTF / 首音、视频帧 / fps、产物和可接受质量；其他设备结果不冒充 Z20。
- **A9 回归与发布：** 旧文本 API / 聊天 / 推荐 / 设置 / 下载通过，原生包与签名、版本 / SHA / 双语说明 / 截图与录屏一致；实际功能演示不能用桌面替身代替。
- **A10 单版范围完整：** v0.3.0 包含 F-01–F-12、既有生文、16 组及其全部冻结子目标，02 的 SD 1.5 / SDXL 配对都通过；不用“有入口 / 能下载”计完成。任一必需目标未过，整体仍未完成，不能默认拆版、删减或顺延。

- **A11 基座 / 模型资产分离：** 零模型安装 / 升级不触发模型网络下载；浏览 / 筛选不隐式下载；仅下载用户所选包及已展示依赖；用户可只装一个模型，App 升级不替换已有权重或强制更新模型；删除模型保留基座，参数和共享引用按明确规则处理。

A1–A4 的规则和部分迁移可先做桌面检查；A5–A8 必须有物理 Android 证据。目前为零。`multimodal-release-scope.json` 是可复查需求快照，不是生产模型清单、下载锁或运行测试报告。
