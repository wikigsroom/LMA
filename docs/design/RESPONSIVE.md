# 云母分区 · 宽窄机型、主题与适配验收

[English](RESPONSIVE.en.md) · [总规范](MICA_BENTO.md) · [组件](COMPONENTS.md) · [Tokens](tokens.json) · [待验收矩阵](acceptance.json)

**本文件定义必须实现的适配，不宣称已有机型测试通过。** 最低可用连续宽度为 240px；更窄时提供可恢复的调大窗口／旋转提示，不自动启动任务。 所有尺寸是可用 WebView 视口的 CSS px；原生安全区与触控尺寸使用 Android 对应单位并实测映射。不能把手机物理 1080px 宽当作布局宽，也不能只按“Z20／X30／平板”写死布局。

## 1. 如何确定布局

以系统栏／刘海处理后的连续可用窗口为基准，读取实际 WebView 布局宽、可视高度、文字比例和必要的折叠遮挡信息。`W` 是扣除原生已占用安全区域后的连续布局宽；选定导航形式后，再计算内容宽 `C = W - 侧轨 - 2 × 页面边距`。键盘打开还需计算可见高度，不能只依赖屏幕纵横比。

宽度档决定列数上限，卡片／字段最小宽、放大文字、短高度和遮挡会进一步降低列数；内容是否放得下优先于“这个断点一定两列”。在相邻断点间平滑填满，不按截图整体缩放。宽度变化不能重置当前页、筛选、草稿、参数、任务或模型服务。

这些是 LMA 的项目断点，不是所有 Android 设备的官方像素分类；其按可用窗口而非硬件分类的原则参见 [Android window size classes](https://developer.android.com/develop/ui/views/layout/use-window-size-classes)。

## 2. R00–R06 宽度档

| 编号 | W 范围 | 单边边距／区块间距 | 模型卡最多列数 | 导航 | 关键处理 |
| --- | --- | --- | --- | --- | --- |
| R00 | <320 | 8 / 8 | 1 | 底栏，可多行 | 极窄分屏降级；全部功能仍可滚动到达，触控不缩小 |
| R01 | 320–359 | 12 / 12 | 1 | 底栏 | 操作下移；资源单列；分段／标签换行；保留完整入口 |
| R02 | 360–479 | 16 / 12 | 1 | 底栏 | 标准手机；资源可 2+1，文本充足时才 3 列 |
| R03 | 480–599 | 20 / 16 | 1 | 底栏 | 宽手机／折叠半屏；多出的宽度用于阅读，不塞第二张窄模型卡 |
| R04 | 600–839 | 24 / 16 | 1 | 底栏 | 资源可 3 列；局部参数可双列，每字段至少 240 |
| R05 | 840–1199 | 24 / 16 | 2 | 80px 侧轨 | 有限多列；不足最小卡宽或短屏仍退单列 |
| R06 | ≥1200 | 32 / 16 | 3 | 80px 侧轨 | 内容最大宽 1200，居中；不无限拉宽消息或输入 |

模型卡在多列时每张至少 320px（200% 文字建议至少 560px），列间距 16px。列数为宽度档上限与 `floor((C + gap)/(minCard + gap))` 的较小值，至少 1。最大内容宽 1200 是阅读与分组约束，不包括侧轨。对话文本最大宽 760；模型库的网格、输入表单和媒体不能盲目共用同一最大宽。

断点边界必须检查 319/320、359/360、479/480、599/600、839/840、1199/1200；边界不存在 1px 空档或重复布局规则。布局用 Grid/Flex、`minmax(0, 1fr)`、内容 `min-width:0` 与逻辑 padding，不通过 JS 缩放整页字体。参考 tokens 不自动提供这些布局代码。

## 3. 首页的具体重排

| 区域 | 窄屏／大字 | 普通手机 | 宽窗口 |
| --- | --- | --- | --- |
| 品牌与设备 | Logo＋LMA＋必要动作；设备／标语移详情 | 允许次级一行或独立换行 | 品牌与页工具栏仍不做宣传横幅 |
| 运行带 | 名称／阶段可两行，动作下移 | 文字与动作同排，放不下就换行 | 保持相同状态和取消／详情路径 |
| 资源 | <360 或 ≥150% 文字优先单列／摘要 | 2+1 或真实可容纳的 3 列 | 3 块同组；不凭空新增统计 |
| 搜索 | 输入占满；清除目标独立 | 同左 | 搜索与筛选仍先于结果，最大阅读宽受控 |
| 五个栏目 | 自然换行，不能缩成无标签图标 | 可一行，必要时换行 | 不把本地入口移入“更多” |
| 六个功能筛选 | 多行完整显示 | 按内容换行 | 功能、来源、内容筛选仍是独立组 |
| 模型卡 | 名称→标签→元数据→整行操作 | 单列，足宽可行内动作 | 按最小宽 2／3 列，原顺序行优先 |

模型列表的顺序由业务决定，与视觉大小无关；不得把原推荐前缀挤到后面。Bento “不等大”只用于资源的装饰比例，不能让某个功能类别或模型天然优先。长模型名／量化后缀完整可读，错误和操作不能被尾部裁切。

## 4. 各业务页的适配

| 页面 | <600 | 600–839 | ≥840 与宽度充足时 |
| --- | --- | --- | --- |
| 模型库／本地 | 单列卡、操作可堆叠 | 仍单列模型；筛选分区可更紧凑 | 模型网格最多 2／3 列；本地管理功能完整 |
| 对话 | 角色消息、媒体、任务卡纵向；输入可两行布局 | 保持舒适文本宽，不为占满强拉气泡 | 会话正文最大 760；仅已有详情可做辅助区，不为布局发明新业务 |
| 任务 | 任务／素材切换或纵向分组；详情独立层 | 表单可局部双列；队列仍可单列 | 步骤／列表＋详情仅在每区够宽时启用；短屏回退 |
| 服务 | 状态→启停→地址→LAN／密钥→模型／示例 | 可将独立信息分组，主操作始终靠近状态 | 主状态与次级接口／日志可双区；密钥与真实地址不省略 |
| 设置 | 整组纵排 | 相关字段有空间可同排 | 可整组双列，不把一个设置的标题与值拆到两列 |
| 模型参数／生成 | 标签、输入、来源／错误纵排 | 每字段至少 240px 才双列 | 控制最大表单宽；完整参数仍跟模型走 |

二级详情不能因侧栏不够宽而丢失，应回退全屏／模态并保留返回路径。横向滑动只用于本来需要二维查看的代码、表格或媒体操作区；普通正文、表单、模型卡和整个页面不允许横向滚动。

## 5. 文字放大、语言和长内容

必须覆盖 **100%、130%、150%、200%** 文字比例，并额外检查系统“显示大小”改变后的实际窗口。100% 时正文 16px；文字比例由实际渲染／原生配置取得，不假定 `devicePixelRatio` 就是字体比例。不要同时应用 Android 字体缩放和另一套 Web 缩放而翻倍；也不得用禁止缩放的 viewport 设置掩盖溢出。

≥150% 采用大字策略：资源与字段优先单列；卡片动作纵排；解除名称／错误行数上限；减少同排元数据；增高标签和导航项。标题不为了留一行而自动缩小。导航图标可保持 24px，但文字与命中区可增长；不能只保留图标。200% 下仍要保存参数、取消任务、发送、切换页和关闭弹层。

中文、英文长单词、混合版本号、`org/repo`、GGUF 文件名和量化后缀都要检查。自然段用换行，长 ID 可 `overflow-wrap:anywhere`；完整值有详情／复制入口。API 代码、hash 和日志可在有名称的局部容器横向滚动，不插入会改变复制内容的断字字符。截图与验收不得包含凭证、口令和个人文件名。

无障碍目标参考 [W3C 320 CSS px 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 与 [200% 文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。这是布局和可用性目标，不把静态文档标为 WCAG 完整符合认证。

## 6. 短屏、横屏和安全区

可见高度 **≤480px** 启用短屏策略，不论方向。顶栏、运行带与资源回到正常滚动流，只保留当前操作必须的输入／导航；不能固定三条工具栏吃掉大部分高度。模态按钮可进入同一内容滚动流。页面存在一个清晰的主纵向滚动容器；聊天消息／编辑框等有必要的内部滚动要有明确边界，不能锁住 body 又没有可滚动出口。

横屏要同时处理左右刘海／圆角、状态栏、手势边缘和三键导航；纵屏无边距通过不代表横屏安全。安全区按原生 `WindowInsets` 与 CSS `env(safe-area-inset-*)` 的实际传递方式选一个所有者：原生已经缩小 WebView 时，Web 不能再把同一安全区加一次；若绘制到系统栏后方，则将可交互区域移入安全范围。参见 [Android edge-to-edge/insets](https://developer.android.com/develop/ui/views/layout/edge-to-edge)。

底栏的 64px 是内容高度，安全区另计；横屏侧轨底部条目可滚动，不能压在手势区。无需精密手势的动作尽量远离屏幕边缘；系统返回优先于 3D 旋转或自定义滑动。两主题的系统栏底色、图标及系统自动遮罩均需要观察，而不只截 WebView 内容。

## 7. 输入法、键盘与可视高度

聊天输入、模型预设、搜索、密钥和生成表单都要检查 IME。优先正确配置原生窗口 resize／insets，再以 `100dvh`、必要的 VisualViewport 监听渐进增强；不依赖旧 `100vh` 永远代表键盘之上的空间。选择单一 IME 高度所有者，避免 native resize 后再减一次键盘高度。旧 WebView 不支持动态单位时用经验证的容器／可视高度回退，不要求引入大型前端框架。

输入焦点、光标、错误及发送／确认必须能滚到键盘之上。IME 出现时可暂时隐藏底导航以让出操作空间，但隐藏项必须从点击与键盘焦点序列移除，关闭后恢复当前入口；不能留下被遮盖的可聚焦按钮。对话保留草稿与滚动，展开预设列表不出屏，横屏数字键盘也不遮保存。

主题切换和键盘展开不能触发模型重新加载。中文组合输入不误发；硬键盘 Tab／Shift+Tab、Enter、Space、Escape 可用。对话中回车换行，明确发送操作；弹框打开／关闭焦点归属符合 C15。不要为了“修复遮挡”全局禁止输入框滚动或强制每次焦点回到页面顶部。

## 8. 折叠、分屏与窗口变化

折叠／分屏实时按当前连续可用区域重算，不按开机时屏幕宽缓存。铰链、遮挡和跨屏空隙不得穿过输入、按钮、消息或关键图像；若原生可提供遮挡信息，应通过受控布局桥传给 WebView。未获得可靠信息时优先使用系统提供的单一连续区域，不声称 CSS 宽度本身能检测铰链。

默认在一个安全连续区运行完整页面；不强制实现跨铰链双页面。只有两个区域各自满足最小宽／高并有真实布局支持时，才可用已有“列表＋详情”；不能跨遮挡画一张大卡。折叠、旋转、调整分屏后保留模型／任务、当前页、搜索、焦点合理位置和草稿；不重新下载或取消作业。大窗口不代表手机内存或模型能力更高。
