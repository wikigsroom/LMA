# dev.21 源码后续：旧 LTX 训练 VAE / Trained VAE follow-up

[中文方案](../LTX098_VAE.md) · [English](../LTX098_VAE.en.md) · [完整同版范围](../MULTIMODAL_RELEASE_PLAN.md) · [开发状态](../../verification/development/status.json)

本轮处理冻结目标17的训练VAE解码。原始BF16权重转F32，九段CPU图按顺序加载和卸载，独立参考执行未修改的原始 `Decoder.forward`。这是源码与组件验证后续，APK/UI媒体继续为 **0.3.0-dev.21 / code25**，不创建新APK、tag或Release。完整v0.3.0保持全部冻结范围。

This adds trained old-LTX decoding as a separately scoped research component. It updates no App code, APK or UI media. Host execution, Android compilation, user acquisition, complete prompt-to-video, output quality and physical-device acceptance are distinct gates. Existing DiT, synthetic-caption sampler and T5 receipts remain unchanged.

## 当前边界 / Current boundaries

外部模型图、权重、统计和原始检查点由用户资产生命周期管理，当前开发工具不会自动获取模型。CLI只核对尺寸/布局/路径/外部引用；完整资产SHA由测试在执行前验证，App集成仍须接入已有完整性管理。研究导出不等于公共一键下载候选，也不表示手机具备模型转换能力。

Raw trained decoder frames are not a complete prompt-to-video demonstration. Tests use explicit random latent/noise inputs, without T5/DiT in this record. F32 decoder parity does not establish BF16 execution, subjective video quality, representative-resolution performance or Android memory suitability. No UI change requires new screenshots or GIFs this turn.
