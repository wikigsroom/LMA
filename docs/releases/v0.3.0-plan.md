## 01 · 状态与版本规则 / Status and version rule

**计划版本：v0.3.0；当前公开 APK：v0.2.0。v0.3.0 正在实施，尚未完整实现或发布；内部 0.3.0-dev 不构成对应公开 APK、标签或 Release 附件。** 本文件是需求交付基线，不是已完成版本的 Release notes。

**Planned version: v0.3.0; current public APK: v0.2.0. v0.3.0 is in development, incomplete and unpublished; internal 0.3.0-dev is not a public APK/tag/Release asset.** This is a delivery baseline, not release notes claiming completed functionality.

用户要求下一版本一次完成全部基座，以及所选模型的运行支持与适配配方。原分版本线路取消；工作包可以按依赖实施，全部进入同一版本、使用同一验收门槛。未解决目标是本版阻塞，不默认删减或顺延。内部测试构建不替代完整交付。

The next version must deliver every selected core/model requirement together. The former split roadmap is withdrawn. Internal work follows dependencies but shares one version and acceptance scope. Unresolved targets remain blockers here, without automatic removal/deferral; internal test builds do not substitute for full delivery.

### App / 模型资产分离 / Foundation and model assets

App 发行只携带基座代码、引擎、界面、目录 / 标签元数据与配方，不携带模型权重或模型专用数据。安装 / 升级不自动下载、选择或替换模型。模型 / LoRA / 编码器 / VAE / codec 权重及模型专用 tokenizer / 音色 / 语言包由用户明确选择后单独下载 / 导入；下载范围仅为所选包及提前展示的必需依赖。

The App ships foundation code, engines, UI, catalogue/tag metadata and recipes, without model weights or model-specific data. Installation/upgrades do not select/download/replace models. Users explicitly choose separate downloads/imports of model/LoRA/encoder/VAE/codec weights and model-specific tokenizers/voices/language packs, limited to the selected bundle and disclosed required dependencies.

用户可以只装一个模型，也可暂不装模型浏览 App；在“本地”独立暂停 / 续传 / 配置 / 更新 / 删除，App 升级保留已有数据。所有目标的开发实测是基座支持能力的验收，不是终端用户全部安装要求。A11 专门验证上述规则。

Users may install one model or browse without any. Local independently manages pause/resume/settings/updates/deletion while App upgrades preserve existing data. Developer testing of every target validates coverage, not mandatory user installation. A11 specifically checks these rules.

## 03 · 产品行为 / Product behavior

- 同一模型库中的推荐 / 全部 / 搜索 / 本地视图；保留推荐 `m08 → m06 → m01` 及原标签 / One library with Recommended/All/search/Local; preserve recommendations, order and labels.
- 功能标签为生文 / 生图 / 生视频 / 生音频；引擎、管线、格式、组件、后端、设备、安装 / 证据与内容标签分开 / Independent output-task, foundation-dependency, compatibility/installation/evidence and content tags.
- 用户选择模型 / 配方、自行下载完整组件、编辑模型独立参数、填写任务表单、提交共用队列、查看 / 保存结果 / Choose a model/recipe, download its complete assets, edit model settings, fill a task form, queue and inspect/export artifacts.
- 数值支持可编辑预设；超出已知硬限制时回填合法上限，保留联合约束与有效值 / Editable presets, correction to known legal maxima, joint constraints and effective snapshots.
- 全部计算在同一手机，无需 ROOT / Termux；显式启动的任务由原生后台持有 / Same-phone execution without ROOT/Termux; native background ownership of explicitly started jobs.
- 不建设 ComfyUI 连线、无限画布、用户节点、插件市场或图导入，不增加外部推理回退 / No ComfyUI wiring/canvas/user nodes/plugin marketplace/graph import or off-device fallback.

## 04 · 统一发布门槛 / Common release gates

R-01–R-05 和 A1–A11 均在完整需求中定义，并共同约束 v0.3.0：全部必需范围真实实现；每个目标有完整固定配方与声明物理 Android 设备的新输入离线输出；后台 / 升级 / 取消 / 恢复 / 资源与质量通过；签名、依赖、哈希、源码、双语说明和功能媒体可复查。

R-01–R-05 and A1–A11 in the full specification apply together: implement all required scope; retain fresh-input offline output for a complete pinned recipe on a declared physical Android device per target; pass background/upgrades/cancel/recovery/resource/quality checks; publish consistent signing/dependencies/hashes/source/bilingual guides/feature media.

“已登记 / 可下载 / 实验”不替代实际输出与验收。某个手机不兼容时禁用该配方；某个纳入目标在任何声明设备都未通过，则本版整体未完成。设备限定不表示必须全部在 Z20 运行。后台至少记录 15 分钟锁屏任务 / 队列与 1 小时空闲 / 请求交替服务，不推导永久存活。

Listing/downloading/experimental labels do not replace execution and acceptance. Disable incompatible recipes on a specific phone; a selected target accepted on no declared device leaves this release incomplete. Not every model must run on Z20. Record at least a 15-minute screen-off task/queue and a one-hour idle/request-alternating service, without inferring permanent survival.
