## 本版行为 / Resulting behavior

手机原先对 Wan 的 Vulkan 能力检查失败，已经下载的权重无法进入生成。现在在 **模型库 → 本地 → Wan → 参数设置** 中选择 `cpu`，保存后新建任务，即可使用相同模型 ID 和现有四个组件在同一手机计算。无需第二份模型描述、重复下载、复制权重或 ROOT。后端选择随模型保存；原默认和旧任务冻结的 Vulkan 选择保留，不静默切换。

Wan previously stopped at the phone's Vulkan capability check. Choose `cpu` under **Models → Local → Wan → model settings**, save and create a new task. The same model ID and installed components use the APK's existing signed CPU worker. Tokenization, UMT5, diffusion, VAE and AVC encoding stay on the phone. The selected backend is per model; old frozen requests and the original Vulkan default are preserved.

Android staging had a second problem: private hardlinks failed, and the native workers still rejected the symlinks introduced in v0.3.10. Canonical leased regular input paths now reach native validation. Components and views retain required filenames with explicit source identity bindings, workspace boundaries and ordinary-source checks. This repair applies across shared 3D, speech and vision entry points without copying weights or accepting arbitrary links.

3D / 语音 / 视觉的共用文件入口现已使用仍受租约保护的普通源路径；必须保留固定文件名的组件和四视图增加身份绑定。未绑定软链接、错误来源和越界目录仍拒绝。TRELLIS/Pixal 增加真实阶段事件；只插入进度回调，不修改模型数学计算，也不生成占位 GLB。

## 真机结果与边界 / Physical results and limits

Actual connected device: **motorola edge plus / burton, Android 12 / API31, SM8250, about 11.4 GiB visible RAM**. This is not a Motorola X30 or Nubia Z20 measurement.

最终 APK 的一采样步 Wan CPU 检查约 **176 秒**，生成可解码的 **H.264 / 128×128 / 5 frames / 8 FPS / 625 ms / 9,173 bytes**。画面接近空白；这是计算、编码、保存和文件校验的流程通过，**不属于可用画质通过**。更早的开发包也完成过一次小尺寸输出，未混入最终 APK 门禁数量。

The final-APK one-step Wan CPU probe completed in about **176 seconds** and produced a decodable **9,173-byte H.264 MP4, 128×128, five frames, 8 FPS, 625 ms**. Its near-blank picture is diagnostic output, not an accepted quality result. An earlier development APK also generated a small output; that run is not added to final-APK gate counts. Selected probes are separately counted and retain each tested APK hash.

Additional final-APK comparison: **four steps / CFG 3**, **347.04 seconds**, **4,885 bytes**; the image is still nearly blank and quality remains unaccepted. [Exact four-step MP4](../media/models/v0.3.11/wan-cpu-128-four-steps.mp4). Both the one-step and four-step outputs are included independently. The public model record contains **four selected attempts / two successful pipelines**; these counts describe that record, not all private preliminary work.

同一最终 APK 的 **4 步 / CFG 3** 复测约 **347.04 秒**完成，视频 **4,885 bytes**，仍接近空白，没有通过画质验收。公开模型记录为 **4 次所选检查 / 2 次流程成功**，与常规程序门禁和更早的开发包检查分开。检查后备份并清理 **4 条自有失败 / 取消任务、4 份自有输入**；原 **2 条成功、5 项素材、5 个已装模型及原参数值**核对保留。

TRELLIS.2 在 600 秒上限内完成图片编码并进入稀疏结构计算；Pixal3D 在 180 秒上限内也到达该阶段。两者随后取消，**均未产出完整 GLB**。原路径错误已越过，CPU 时间仍是实际限制。TRELLIS 的记录保留其确切中间安装包身份，不能改标成最终 APK。

TRELLIS.2 reached sparse-structure computation after image encoding, then was cancelled at its 600-second budget. Pixal3D reached the same stage within its 180-second budget and was also cancelled. Neither produced a complete GLB. TRELLIS retains its actual intermediate-APK identity. Entering computation does not establish normal usable 3D generation.
