# App 基座与用户模型资产：需求核对

[English](ASSET_CONTROL_AUDIT.en.md) · [完整版本需求](MULTIMODAL_RELEASE_PLAN.md) · [版本摘要](releases/v0.3.0-plan.md) · [实际开发状态](DEVELOPMENT.md)

核对日期：2026-10-28。**当前需求文档符合“App 仅更新基座，模型由用户自行选择、下载、管理”的要求。** 文档符合不表示完整功能已实现或真机已验收。

| 用户要求 | 现行文档约束 | 当前实现 / 验收状态 |
| --- | --- | --- |
| APK 更新只提供基座 | 版本计划的 App / 模型资产分离条款；F-02 / A11 | APK 包检查排除权重、模型专用词表和音色；新增引擎属于 App 代码 |
| 用户自行选择模型与依赖 | 下载所选包及事先展示的完整必需组件；不强制安装全部支持目标 | 包详情 / 显式下载 / 文件夹导入已接入；HF 多组件配方选择仍待完成 |
| 安装、升级、浏览不自动下载 | 结构化范围的 `model_asset_policy` 明确禁止隐式选择 / 下载 / 替换 | 桌面存储 / 传输 / UI 检查覆盖声明、浏览和缺资产失败；真实 Android 安装 / 升级仍待验证 |
| 独立管理模型 | 本地支持暂停 / 续传 / 设置 / 导入 / 更新 / 删除；App 升级保留用户文件 | 已实现其中多项；独立模型更新流程和完整旧版迁移仍未完成 |
| 生文 / 生图 / 生视频 / 生音频标签 | 同一平级数据池，功能标签与引擎 / 架构 / 格式 / 组件 / 后端及证据标签独立 | 四种功能筛选已写入；标签不能替代实际模型执行支持 |
| LoRA 等组件也由用户管理 | 模型 / 适配器平级，显式兼容基础依赖；A1 / A11 | dev.4 增加独立 LoRA 包、配对 / 强度 / 任务引用；真机效果未验收 |
| 以后继续扩展模型 | 已支持架构可增加独立资产配方；新架构需要基座代码与签名更新 | 当前有文本、扩散、语音实际引擎代码；不是任意 HF 权重即装即用 |
| 全本机与单一下一版本 | 同一手机执行；F-01–F-12 与 01–14 / 16 / 17 共用完整 v0.3.0 门槛 | 没有外部推理方案；完整目标与物理设备验收尚未完成，无新 Release |

需求依据已同时出现在 [中文需求](MULTIMODAL_RELEASE_PLAN.md)、[English requirements](MULTIMODAL_RELEASE_PLAN.en.md)、[发版摘要](releases/v0.3.0-plan.md)、[结构化策略](proposals/multimodal-release-scope.json)、[仓库约定](../AGENTS.md)与[发布流程](RELEASING.md)，彼此没有要求终端用户全量下载模型的冲突。

后续按 A11 验收零模型安装 / 升级、浏览无下载、显式选择范围、模型独立更新、升级保留和共享资产删除保护。**结论：需求基线一致；实现和设备验收继续逐项补齐。** 不应把模型目录登记数、下载成功或桌面演示当成手机已支持模型数。
