# 对话页面复原与生成能力融合 · 2026-11-06

[English](CHAT_RESTORE_20261106.en.md) · [README](../README.md) · [v1.0.1](releases/v1.0.1.md) · [既有对话、工具与 API 合同](CONVERSATION_V040.md)

## 1. 结论与本轮范围

恢复 v0.3.x 的聊天信息结构：**顶部选模型／历史／新建 → 中间消息 → 底部输入／发送**。保留已定稿的 UI10 明暗主题、Logo21、模型资产与既有后台任务。v1.0.1 将已经实现的媒体创作入口放进“＋”功能面板，普通聊天不再常驻创作表单。

下文 4–7 是对进一步融合的评估，不能把建议中的新交互写成已实现。无需重做推理引擎、另建模型库、引入远程推理或 ComfyUI 节点体系。

## 2. 为什么上一版不好用

| 编号 | 检查到的问题 | 影响与修复 |
| --- | --- | --- |
| P01 | 两个下拉框、附件／参数／模板／视觉配对／历史五按钮及说明常驻输入区 | 48px 触控尺寸及整行模型选择使表单挤占消息；移到按需打开的面板 |
| P02 | 顶部与输入区重复选择模型 | 恢复顶部唯一常驻入口；创作面板只在非对话模式显示生成模型选项 |
| P03 | 下拉框第一项为“旁白文字”，内部实际默认为 chat | 明确同步初始 chat 值；避免用户误判即将执行的操作 |
| P04 | 新渲染器跳过旧函数，顶部模型名没有更新 | 依据当前原生引擎／所选生成模型刷新标题；文本选择跟随实际引擎 |
| P05 | 大 Logo、品牌标语取代起始问题，消息复制入口丢失 | 恢复“从一句话开始”、两个起始问题与助手消息复制；品牌仍保留在应用顶栏和关于页 |
| P06 | 模型库能力筛选影响聊天模型选项 | 聊天按本机已安装及当前任务能力选模型，避免发现页筛选使已加载模型不可选 |

这些是页面信息层级和状态同步问题；不能由界面密度推断推理变慢。空闲性能与模型速度单独记录。

## 3. 本版操作与实现

| 编号 | 操作 | 当前行为 |
| --- | --- | --- |
| U01 | 普通对话 | 顶部选已下载文本模型；加载后输入并发送。回车换行，Ctrl／Cmd+Enter 发送；历史使用有界分页 |
| U02 | 点击输入区“＋” | 打开“对话与创作”；可选普通对话、自动、手动生图／视频／配音／音乐／3D／旁白或本机合成 |
| U03 | 手动媒体任务 | 选择已安装的兼容生成模型，按需设置附件角色／本次参数；“返回对话”关闭面板后发送，不要求加载语言模型 |
| U04 | 非普通模式 | 输入框上方仅增加一个模式摘要和“回到普通对话”；顶部显示该任务所选模型 |
| U05 | 附件、参数、模板、视觉配对 | 从“＋”进入原有功能；已选附件及用途显示在输入区，临时参数不覆盖逐模型默认参数 |
| U06 | 自动模式 | 明确选择后才允许模型提出工具草稿；审核后执行，普通文字不会自动变成指令 |
| U07 | 返回、嵌套面板、主题切换 | 保留当前输入、已选模式与设置；面板使用现有焦点约束／背景隔离，退出时还原焦点 |
| U08 | 结果与后台 | 保留原任务 ID、真实进度、错误、取消／重试与媒体引用；关闭对话页释放预览播放器，原生任务继续持有执行 |

代码仍使用 `LMAConversation`、生产桥接和共享任务库。功能面板控件只有一个实例，在弹层与隐藏停放位置间移动；打开另一弹层前停放，避免控件被替换、事件丢失或草稿重置。默认输入区不再挂载常驻下拉表单。消息仍最多挂载 60 条，1000 条记录通过游标读取；媒体不自动解码。

## 4. 推荐的完整融合结构

| 编号 | 需求 | 建议交互 | 可行性与当前边界 |
| --- | --- | --- | --- |
| F01 | 聊天与全部生成模型共存 | 默认聊天；“＋”展开生图／视频／音频／3D／合成等任务入口；选择后只显示当前任务摘要 | 高；本轮完成收起入口，后续可把长模式列表改为有名称和图标的任务网格 |
| F02 | 统一选模型 | 顶部按任务筛选本机可用模型；按类型／能力／组件／安装状态标记；未下载项明确前往模型库 | 高；当前已恢复唯一常驻入口；统一可搜索选择面板仍是建议 |
| F03 | 参数与模型一起走 | 默认使用逐模型配置；本次覆盖放参数面板并显示已修改数量；保存为默认必须另行确认 | 高；逐模型保存和临时覆盖已有，修改数量摘要及明确重置入口待做 |
| F04 | 多模态输入 | 附件以缩略图／音频条呈现；选择用途并预检；视觉 GGUF 与 projector 在“本地模型”配置后，聊天只显示可用状态 | 中；受管引用、用途、身份核对已有；缩略展示、前置兼容提示与配对页面迁移待做 |
| F05 | 生成结果融入消息 | 一个原任务对应一张紧凑卡：排队→实际阶段→结果；点开查看参数、错误或大预览 | 高；原任务卡和惰性预览已有，可继续简化可读摘要；不得造进度或重复执行 |
| F06 | 连续创作 | 结果卡提供“作为图片／视频／配音／3D 输入”，自动带入引用；发送前确认模型、用途和参数 | 中；引用和原任务关系已有；按能力列出下一步操作及完整交互预检待做 |
| F07 | 自动与手动互通 | 手动不依赖 LLM；自动只提出可编辑计划，用户确认后执行；工具结果回到同一消息流 | 中；现有审核／去重／续写合同可复用，小模型工具可靠性仍不能保证 |
| F08 | 多步需求 | 从模板面板使用 W01–W06 顺序步骤；用表单查看模型、输入、依赖与失败步骤，不做连线画布 | 高；顺序模板与单步重试已有，面向普通用户的步骤摘要和角色表单仍可改善 |

**建议选择 F01–F08 作为一套完整交互目标。** 默认视图保持三段结构；只有用户选中的任务、附件、参数变化和真实任务状态进入主页面。能力复杂度由面板承载，而不是把所有引擎字段永久铺在输入框上。

## 5. 状态与数据规则

1. 任务类型由用户显式选择；普通对话不因“画一张”等关键词静默切换模式，也不自动下载模型。
2. `modelId`／`bundleId`、任务类型、附件引用及角色、临时参数、待确认工具计划分别持有；显示名称不能替代稳定 ID。运行中任务固定已接纳配置，切换聊天模型不改写排队任务。
3. 参数优先级为当前模型默认 → 用户本次覆盖 → 原生约束归位。空值／未知上限／不支持字段明确反馈，不用另一个模型的上限。
4. 工具必须经过现有白名单、模型／组件、资源、素材和幂等校验。模型提议与用户批准是不同状态。
5. 同一 `jobId`／artifact 引用在聊天、任务页和 API 中保持同一身份。重连恢复查询原任务，不重复提交；重试保留原任务关系，失败不清洗成成功。
6. 只有匹配模型及组件真的可用时才标记支持理解输入。图片生成能力不是图片理解；TTS 不是 ASR；媒体合成不是 AI 生成模型。
7. 模型推理、编解码及合成都在同一 Android 手机。用户明确取消、资源不足、温控和系统进程终止仍需处理；生成没有固定墙钟上限不等于无限资源。

## 6. 示例流程与验收

| 编号 | 示例 | 应验证的闭环 |
| --- | --- | --- |
| A01 | 只聊天 | 打开页面看到原三段布局；只选择一次模型；流式回复、复制、历史、停止可用 |
| A02 | 不装 LLM 直接生图 | “＋”选生图和已有图片模型，输入提示词后提交；语言模型缺失不成为前置条件 |
| A03 | 图片 → 视频 | 从结果引用图，明确视频模型及输入角色；目标时长 >5秒并服从实际帧数／帧率约束；没有可用模型则引导选择，不自动下载 |
| A04 | 配音／音乐 → 成片 | 显式区分 voice／music／visual；复用同机合成，显示真实文件与编码失败 |
| A05 | 图片 → 3D | 只在模型有匹配 image 输入合同时提供；预览 GLB 按需加载，不把图片预览冒充 3D 成功 |
| A06 | 自动工具 | 展示建议模型／参数／素材并人工确认；取消审核不创建任务；失败保留草稿或原任务 |
| A07 | 面板及设备适配 | 关闭／重开、嵌套参数、系统返回、主题切换不丢输入；窄屏、横屏、键盘、大字有可达操作 |
| A08 | 后台与恢复 | 页面退出不接管／终止原生执行；重新打开查询原进度，媒体播放器及时释放，不宣称无限后台 |

## 7. 本轮证据与保留边界

当前界面程序检查使用生产 HTML／CSS／JS 加明确标记的模拟原生桥，验证 100 会话、1000 消息、100 素材和全部手动操作；[截图与录像来源](media/conversation-v1.0.1/manifest.json)。[版本程序记录](../verification/releases/v1.0.1/status.json) 和 [实机界面记录](../verification/releases/v1.0.1/mica-physical-ui.json) 分开，真机材料见 [来源清单](media/device/v1.0.1/manifest.json)。

本轮不下载或完整运行模型，不把页面恢复当作画质、音质、任意 HF 权重可运行或长期后台保证。m03／m09／m16 等视觉组件的公开配对身份、完整 codec 输出、视频／3D 质量和耐久限制延续原记录；F01–F08 中明确列出的建议交互尚未全部实施。
