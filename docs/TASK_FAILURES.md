## 2. 修复细节

`EngineWorkspace` 先尝试硬链接；系统不允许时，检查源是普通文件、目标不存在，再建立指向同一私有源的软链接，核对目标一致。模型租约继续持有源文件，清理只移除工作链接，不遍历或删除源对象。目标已存在、源是软链接或两种链接均不允许时明确失败，不覆盖文件，也不复制数 GB 权重。

生产 `NativeWorker` 将结构化事件与 stderr 分开读取，持续排空 stderr 以免阻塞子进程，只保存有限、白名单化的诊断码。任务详情保留有效参数、执行结束标记、退出码和诊断码；原生明确错误优先于通用提示，不把原始提示词或文件路径作为诊断日志发布。MNN / Sana-Sprint、MOSS delay 与 Qwen TTS 的先前执行参数也随结束信息保留。

Wan GPU 配方在预检与实际启动前调用签名引擎的 `--devices`，不载入权重。检查有时间与输出上限；正向结果缓存，不在目录刷新或空闲界面中反复探测。失败时停止提交，不静默改为 CPU。此手机实际返回 `Vulkan 1.2 required` 和 CPU 列表；APK 不能改变驱动能力。

## 3. 可选 Wan CPU 配方

[用户可导入的 CPU 描述文件](examples/wan21_13b_q4_cpu_phone.json) 是元数据，没有模型权重。ID 为 `wan21_13b_q4_cpu_manual_v1`，使用 `sd_cpp` CPU 引擎与 `wan21_13b_split_cpu_v1` 配方。

1. 用户自行下载这个 JSON，然后在模型的本地管理中使用“导入模型包清单”。
2. 检查显示的 CPU 标签、四个组件、固定来源、许可证与下载计划，再明确选择安装。
3. 与原 GPU 包相同且校验有效的对象可复用；缺少组件才按用户确认下载。两种配方保持独立身份和逐模型参数。
4. 在任务表单中明确选择新 CPU 包并提交；此操作可能很慢，资源要求与完整生成结果本轮未测。

诊断过程**没有替用户导入、下载或运行该 CPU 包**，也没有改动默认 82 包目录、14 项推荐或用户原 GPU 包。该文件只为提供可审查的明确替代路线，不构成 CPU 完整视频成功保证。

## 4. 清理与保留

逐条清理前，保存原任务、模型设置、素材身份及诊断到本机忽略目录 `build/device-task-audit/`。每次删除前重新读取对应记录，核对仍是同一条终态失败记录；仅删除这 5 个任务 ID。清理后核对：

| 编号 | 结果 |
| --- | --- |
| P01 | 5 条失败记录均有本机私有备份，随后从任务列表移除 |
| P02 | 2 条成功任务的完整记录保持一致 |
| P03 | 5 项素材 / 结果保持一致，未删除用户输入和输出 |
| P04 | 5 个已安装模型、安装标记和逐模型参数保留；草稿未清理 |
| P05 | 三个问题模型涉及的 17 个组件均存在、大小匹配、安装校验记录有效 |

私有备份、提示词、用户媒体、密钥和设备连接信息不进入 Git 或 Release。[公开诊断 JSON](../verification/releases/v0.3.10/task-diagnostics.json) 只包含编号、模型身份、耗时、原因和检查结论。

## 5. 验证与剩余边界

真机通过四字节链接探针、17 组件元数据核对、Wan `--info` / `--devices` 与生产预检“不排队”检查，另做界面 / SQLite / 接口与约 60 秒锁屏服务程序检查。主机回归使用生产类和明确的小夹具，覆盖分离 stderr、无换行诊断、结构化错误、非零退出、执行参数保留和 CPU 描述验证。

| 编号 | 尚无结论 | 后续方式 |
| --- | --- | --- |
| U01 | 修复后的完整 TRELLIS.2 / Pixal3D 生成、画质、峰值 RAM | 已修复所定位的准备阶段；按用户要求不主动运行完整模型 |
| U02 | 本机 Wan CPU 完整输出和用时 | 可由用户自行选择 CPU 包；未替用户试跑 |
| U03 | 当前 Wan GPU 驱动能力 | 当前配置不兼容；需要满足引擎要求的驱动 / 设备，不能靠重试或 App 补丁补齐 |
| U04 | 长时间推理与锁屏耐久 | 60 秒检查只证明程序接口短时存活 |
