# 生成业务闭环：草稿、任务与素材

[English](TASK_WORKBENCH.en.md) · [首页](../README.md) · [完整版本范围](MULTIMODAL_RELEASE_PLAN.md) · [本轮编号交付](releases/v0.3.0-dev.25.md)

`0.3.0-dev.25` 将生成表单、草稿、历史任务和素材库连接起来。代码已进入 APK；桌面文件、接口与界面检查不代表 Android 推理或后台时长验收。App 只更新基座，模型仍由用户选择、下载、导入和管理。

## 使用顺序

1. 在“模型库 → 全部 / 搜索”选择模型，核对生文 / 生图 / 生视频 / 生音频、引擎、组件和设备状态，主动下载或导入。推荐仍保留 `m08 → m06 → m01`。
2. 在“本地”选择已安装模型，填写提示词、参数、LoRA 和该配方接受的参考素材。模型设置是此模型的默认值；“本次参数”只用于这次请求。
3. 暂时不生成时，点击“保存草稿”。允许提示词尚未填写，也不要求勾选试运行。每个模型保留一份，后续保存会更新同一份草稿。
4. 从“任务 → 生成草稿”点击“继续编辑”。恢复提示词、任务类型、本次参数、LoRA 强度、素材 ID 和参考原文。再次提交需要主动确认；恢复本身不执行任务。
5. 提交后，在任务详情中查看可读的输入、参数、LoRA、参考素材和错误。完成后直接“打开结果”，也可以“编辑后再次生成”。完整执行记录仍可展开查看。
6. 在结果预览中点击“恢复生成参数”，或将图片、音频、视频“用作下一次素材”。后者只列出已安装、当前引擎可用且声明接受该文件类型与尺寸 / 时长范围的配方与输入角色。填入表单后再填写提示词并提交。

导入媒体没有生成来源，不能假装恢复生成参数；它可以作为匹配配方的参考素材。删除历史任务后，仍可从保留产物的来源记录恢复生成请求。删除参考素材后，只要任务或产物来源记录仍保留，就可恢复原请求；缺失的输入必须重新选择或经明确检查后移除。

## 恢复时发生了什么

`TaskRequests` 是 UI、API 和失败重试共用的请求重建代码。它只保留用户可编辑的模型 ID、类型、输入、参数和 LoRA；执行回执、旧组件校验、资源决策及未来新增的服务端字段不会重新作为用户请求传入。

编辑恢复与读取草稿始终取消旧的试运行勾选。明确点击“重试”保留原请求的用户选择，但仍重新检查当前文件、配方、参数与资源。准备 / 关联任务保留原来的签名方案并重新校验，不能打开成生文 / 生图表单。

当前配方如果不再接受原参数、LoRA 或参考素材，表单逐项列出问题，并增加必选的检查确认框。数字字段继续按该模型当前约束归位；缺失的必需输入仍会阻止提交。所有新任务重新经过生产 `LocalJobs`，形成新的不可变快照。恢复功能不承诺权重更新后输出相同像素或音频。

## 草稿的保存和独立管理

草稿位于 Android App 私有的 `task-drafts/drafts.json`，使用 `AtomicFile` 持久化。只有点击保存才写入；关闭尚未保存的表单不会自动提交或开始下载。重启及普通 App 升级保留草稿，实际升级行为仍需手机验收。

每个模型一份，最多 128 份，总索引上限 8 MiB。草稿不包含权重或媒体副本，不占用执行槽，不锁定模型，也不保护引用素材免于删除。模型文件、模型设置、任务、草稿和产物分别管理；恢复时校验当前引用。草稿索引损坏时保留原文件并单独报告，其他基座模块继续初始化。

每次写入返回递增 `revision`。App / API 保存或删除时必须提供所见的 `expectedRevision`；有更新则报冲突，避免覆盖其他编辑。删除后再创建也不会复用旧版本号。草稿写入失败不改变已保存版本。

## 本地 API

全部接口继续使用现有 Bearer key；浏览器 Origin 限制、请求大小和现有监听策略保持生效。API 客户端提交到手机，由手机执行；没有外部推理提供方。

| 方法与路径 | 行为 |
|---|---|
| `GET /v1/drafts` | 草稿摘要，含 `bundleId`、`type`、`savedAt`、`revision`、输入摘要 |
| `GET /v1/drafts/{bundleId}` | 完整草稿请求和版本号 |
| `POST /v1/drafts` | 保存 `{request, expectedRevision}`；首次为 `0`，更新用当前版本号 |
| `POST /v1/drafts/{bundleId}/delete` | 以 `{expectedRevision}` 删除所见版本 |
| `GET /v1/jobs/{id}/request` | 取得生成任务的可编辑请求；不提交新任务 |
| `GET /v1/artifacts/{id}/request` | 从本机生成结果的来源恢复请求；导入媒体不适用 |
| `POST /v1/jobs` | 用户完成修改、确认后，通过既有队列提交新请求 |

保存示例（模型 ID 应换成用户实际选择的 ID）：

```json
{
  "expectedRevision": 0,
  "request": {
    "bundleId": "selected_model_id",
    "type": "image.generate",
    "input": {"prompt": ""},
    "parameters": {"seed": 42},
    "allowUnmeasured": false
  }
}
```

更新 / 删除过期版本返回 `409`，不存在的草稿返回 `404`，非法请求返回 `400`。API 保存 / 删除成功后通知 App 刷新。读取编辑请求不会生成任务；提交时仍要求当前模型和全部必需资产可用，缺失资产不会自动下载。
