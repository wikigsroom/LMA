[English](MODEL_UPDATES.en.md) · [HF 组件配方](HF_RECIPES.md) · [开发状态](DEVELOPMENT.md) · [资产边界核对](ASSET_CONTROL_AUDIT.md)

适用：**0.3.0-dev.10 / code 14，内部检查点，尚未发布完整 v0.3.0**。App 更新提供基座；模型版本是用户单独管理的数据。当前流程适用于通用 `ModelBundle`；dev.9 已将原有完整 GGUF 记录接入同一资产、参数与版本管理，详见[迁移指南](MODEL_MIGRATION.md)。[共用调度](SCHEDULING.md)已接入；全部模型适配和 Android 升级验收仍待完成。

## 使用步骤

1. 先在“全部 / 搜索”的 HF 文件页选择配方，绑定新版本的固定组件并登记，或导入具有新 ID 的模型包清单。登记、浏览和核对不下载资产，也不自动寻找或接受新版本。
2. 在“本地”打开现有模型详情，进入**版本管理 / 独立更新**，选择目标及参数策略。候选必须保持相同引擎、架构、管线、后端、输出功能和 LoRA 基础兼容约束；其他模型仍可作为独立平级条目添加。
3. 核对每个组件的新增 / 移除 / 内容变化 / 来源变化、固定仓库 revision、路径、格式、大小和预期校验。详情同时展示完整大小、可复用资产、剩余传输、可用存储、许可与能力变化。版本关系由用户指定，不代表发布者已证实二者是同一发布序列。
4. 明确点击**确认并下载新版本**，或**确认并从文件夹导入**。仅处理选中的包及已展示组件。下载期间保留旧文件；空间不足时本机报错，不自动清理旧版本，也不转向外部推理。暂停 / 继续仍使用同一个组件传输器；不因重启或 App 升级恢复下载。
5. 校验和安装完成后，旧版本仍是当前版本。再次核对，点击**确认设为当前版本**才提交切换。此操作不启动推理，也不改写已有任务。旧资产和参数保留，需释放空间时由用户单独删除。
6. 回退时选择已保留的旧版本，通常选择“保留目标版本原有参数 / 默认值”，再确认切换。已删除的旧文件必须由用户重新下载 / 导入并校验；不会自动补齐。切换记录保留最近 64 次操作。

所有版本保持平级、可单独查看和使用。“当前版本”是持久的用户偏好标记，不是把固定 ID 指向另一套权重的别名。没有模型也能使用 App 的浏览与管理功能。

## 参数与确认

“沿用当前版本参数”只迁移兼容的字段，并按照目标 schema 归位数值。移除的参数不带入，新字段用目标默认值；类型改变、失效枚举、超长文本会明确展示重置原因。编译尺寸组合不兼容时只将联合尺寸恢复为合法默认组合，其他参数继续按目标约束处理。

“保留目标版本原有参数 / 默认值”适合已有自定义配置的目标和回退，不覆盖该版本的设置。两种策略均在确认前展示结果；源版本参数始终保留。约束来自配方 schema，未知硬件 / 模型限制仍需各引擎和设备准入验证，不因为迁移成功而成为已核对上限。

原生端生成确认指纹，绑定两份不可变清单、两版有效参数、版本组代次及策略。确认后任一配置或当前版本变化，旧确认失效；已有计划先取消再重新核对。传输进度不影响确认；下载成功也不能代替启用确认。

## 失败、任务与存储

- 校验失败、下载失败、暂停或中断不改变当前版本和旧参数。取消计划会暂停正在进行的目标传输，保留已经获得的资产，后续清理由用户选择；它不会终止无关传输。
- 安装、启用和删除是不同操作。启用以一次 AtomicFile 元数据提交写入偏好、目标配置及切换记录，不移动 / 重命名权重，不自动删除旧文件。
- 运行中的任一版本租约会阻止启用时的配置覆盖。排队 / 运行任务引用的主模型和 LoRA 都禁止删除；提交与受保护删除共享存储锁，避免检查与操作之间的竞态。
- 已提交任务继续使用原 `bundleId`、适配器 ID、参数快照和完整性回执。`/v1/models` 列出已安装的固定版本，附 `version` 元数据；API 不把旧 ID 隐式重定向到新版本。
- 旧 `lma.bundle-store/1` 元数据兼容增加可选 `versions` 索引；原清单、对象路径和独立设置不变。共享组件仍按引用保护，删除一个版本不会移除另一个已安装版本需要的文件。
- 新权重的来源、许可、功能和内容标签以新清单为准，不继承旧版的设备验证或已核对无审查标记。更新来源声明不能代替运行兼容性验证。
