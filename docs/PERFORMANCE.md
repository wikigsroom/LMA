# 空闲界面性能与修复 · v0.3.9

[English](PERFORMANCE.en.md) · [Release](releases/v0.3.9.md) · [原始数字与身份](../verification/releases/v0.3.9/ui-performance.json)

即使没有加载模型，v0.3.8 每次状态更新仍在 Android 主线程遍历完整 82 包目录，重复构造并校验不可变模型描述、多次解析同一参数 schema，再序列化约 954 KB 状态。主线程被占用期间，点击、滚动和原生页面操作都会等待。前端还会重复生成模型视图、刷新隐藏页面和重新创建未变化的推荐计数。这些是基座代码的开销，与实际模型推理无关。

之前已有 60 ms 广播防抖、模型卡片 / 聊天消息签名去重和服务通知节流，但防抖不减少单次工作，也不会把工作移出主线程；页面签名之前仍会执行目录生成和计数修改。原来的功能检查没有记录状态整理耗时和主线程间隔，这是验证缺口。源码未发现持续重建目录的固定空闲轮询；问题发生在启动及状态广播的处理路径，不能写成“空闲时一直在推理”。

## 1. 同一台真机、相同测量程序

实际设备为 motorola edge plus / burton，Android 12 / API31，SM8250，约 11.4 GiB 系统可见 RAM。先测未修改的正式 v0.3.8，再以原签名原地升级 v0.3.9；没有安装完整模型，没有执行推理。原有未安装本地条目或传输记录不删除，不算已安装模型。此记录不代表 X30 或努比亚 Z20。

| 测量 / Measurement | v0.3.8 | v0.3.9 |
| --- | ---: | ---: |
| 状态序列化 p50 / Snapshot serialization p50 | 4061.09 ms | 229.85 ms |
| 模型目录 p50 / Bundle catalogue p50 | 3853.89 ms | 184.08 ms |
| 主线程最长间隔 / Maximum main-thread gap | 4228.00 ms | 24.00 ms |
| 超过 100 ms 的间隔 / Gaps over 100 ms | 1.00 | 0.00 |
| 12 次更新的视图生成 / Model-view builds over 12 updates | 72.00 | 12.00 |
| 12 次更新的页面修改 / DOM mutations over 12 updates | 699.00 | 118.00 |
| 前端更新平均 / Mean receive execution | 4.95 ms | 1.31 ms |

状态序列化包含完整 JSON 输出，七次暖态取 p50；目录五次取 p50。主线程每 16 ms 安排一次回调，测试线程以 300 ms 间隔发送八次普通状态广播，记录回调间隔，**不是 FPS 或输入延迟测试**。前端在“推荐 / 所有功能”页面对同一状态调用十二次 `receive`，统计同步执行、公开视图方法调用和 DOM 修改。两个版本均保留 82 包、14 张推荐卡片；完整数字、APK SHA256 和诊断程序指纹见链接。优化后的整理发生在后台，不能把后台 230 ms 误称为每次点击停顿 230 ms。

## 2. 实际修复

| 编号 | 改动 | 保留的正确性 |
| --- | --- | --- |
| P01 | 单一后台线程整理与编码状态；广播防抖，忙时只合并一个后续请求 | 主线程只交付结果；停止 / 销毁页面不交付过期结果，重新进入拉取新状态 |
| P02 | 复用按不可变版本 ID 校验的 ModelBundle；每包每次快照只解析一次参数 schema | JSON 对外仍是副本；文件、完整性回执、安装状态、配置、版本和租约每次读取；执行路径重新校验 |
| P03 | 前端每次接收状态只构造一次共用模型视图 | 每次新状态使视图缓存失效；保留所有模型、推荐前缀、NSFW 与独立参数 |
| P04 | 模型 / 聊天 / 接口按可见页面刷新；不重建未变化计数、主题和运行提示 | 打开页面立即刷新；任务、命令确认和参数保存回调继续处理 |
| P05 | 每次启动对每个独立签名原生文件只读取一次 SHA256，复用同一启动期间的共享依赖结果 | 每次新进程仍验证每个不同文件，始终与每一条签名清单对照；无跨启动跳过验证 |
| P06 | 新增缓存副本隔离、单次 schema 解析、前端重复更新与真机性能回归记录 | 不缓存权重、不取消校验、不下载或运行训练模型 |

## 3. 如何复测

仅原生 Windows 工具；不运行虚拟机或模拟器。手机须已配对无线 ADB、ARM64 / Android 12+ 并解锁（当前诊断读取 API31 的 SoC 字段；主程序仍支持 Android 9+）。`tools/build_acceptance.py` 构建诊断包；`tools/profile_device.py --serial DEVICE --label optimized` 执行有界测量；`tools/performance_evidence.py` 核对历史 v0.3.8 和当前 APK 身份并导出数字。原始状态、API 密钥、个人模型内容、调试网络地址和密码不写入公开记录。只对准备好的无已安装模型设备使用专项；不会清除用户数据。

## 4. 尚未量测

本次只修复并验证一个实际设备的暖态程序路径。冷启动时间、耗电、长时间后台、持续 FPS、不同厂商 / 系统版本，以及完整模型的速度、峰值 RAM 和质量均无新结论。目录仍完整整理和序列化，约 1 MB 状态传输仍有成本；后台合并和视图复用已经去掉本次确认的数秒主线程阻塞，不承诺所有设备零卡顿。完整训练模型验证按用户要求不运行。
